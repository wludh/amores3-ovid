# Amores 3.7, witness Y: initial TEI and display review

Reviewed: 2026-09-08. This is an initial audit, not a completed diplomatic transcription or a declaration of TEI validity. No transcription, stylesheet, or annotation data was changed.

## Evidence and scope

- Website source: `docs/data/witness-Y.xml`, poem 3.7; 86 lines in 43 couplets.
- Earlier example: `docs/data/three.7YTranscription.txt`. It differs from the website XML and fails XML parsing at line 21 because the prose description contains unclosed example tags. The website XML parses successfully; XML well-formedness does not establish schema validity.
- Browser inspection: local website, transcription 3.7/Y. Observed wrapping, odd-line-only numbering, concatenated alternatives, missing glyphs, and inline marginal-note presentation.
- Manuscript evidence: directly inspected the full images of fols. 63r and 64r, with enlarged views of opening corrections and the ending. Fol. 63v has not yet received a visual audit in this review. No complete line-by-line verification is claimed.
- Local Y manifest identifies Staatsbibliothek zu Berlin, Ms. Ham. 471, and supplies the date string `[10./11. Jh.]`. The XML's generic description of a late-medieval hand is insufficient and needs to be reconciled with the catalogue and any later correcting hands.

## Priority findings

### 1. Recheck the transcription against images before polishing it

The ending on 64r visibly contains the sequence beginning `Nec mora desiluit tunica uelata soluta` and ending `Dedecus hoc sumpta dissimulauit aqua`, followed by the large initial of 3.8. These are reading-level identifications, not a finished character-by-character encoding. The XML instead has `Nec potuit cupido ...` at 81, `Nudaque deiecto basia fecit equo` at 82, and four additional lines ending `Utilis & facilis concolor herba fuit`. Its 81–86 cannot be accepted as a transcription of this image. Line 80 also needs rechecking.

At the opening, the small `le` above line 3 and the supralinear material near `posuit` in line 10 require accurate anchoring and semantic classification. The existing line 10 places literal `sup` after `posui`; the image shows supralinear material before the word. Do not silently discard it as a coding artifact or accept its current placement.

The unexplained vertical bars, slashes, punctuation, and forms such as `tantŨ` should all enter a verification queue. Preserve genuine witness readings; do not substitute a modern edition merely because its Latin is familiar. Record unreadable or doubtful material explicitly.

### 2. Distinguish what a mark does from how it looks

The file relies heavily on `hi rend="sup"` and `hi rend="alt-ink"`. Superscript position alone does not identify an abbreviation, correction, gloss, or alternative reading. Use `abbr`/`expan` and, where needed, `am`/`ex` for abbreviations; `add` for actual additions; `subst` for linked deletion-and-addition interventions; and suitable `note`, `metamark`, or other elements after interpreting the evidence. Hand attribution needs evidence and documented identifiers, not just a darker color. [Primary Sources](https://tei-c.org/release/doc/tei-p5-doc/en/html/PH.html), [subst](https://tei-c.org/release/doc/tei-p5-doc/en/html/ref-subst.html).

Specific cases: line 39's adjacent `del` and marginal `add` should be assessed as a possible substitution; line 36's `iñ (marginal)` needs the manuscript content separated from the encoder's explanation, plus a verified position and target.

### 3. Fix rendering that loses or changes information

| Current example | Issue | Proposed behavior |
| --- | --- | --- |
| Empty `g` elements | Their mappings are not resolved by the current renderer; marks disappear. `#apostrophe` is undeclared. | Resolve declared glyphs, supply accessible descriptions, and flag unresolved references. |
| `space quantity="2" unit="char"` at line 6 | Encoded blank has no width behavior. | Render intentional blank space; distinguish a source blank from loss or illegibility. |
| `choice/orig/reg` at line 81 | Both alternatives display consecutively. | Select the appropriate branch for the chosen reading mode and expose the alternative separately. The underlying reading still needs correction. |
| `del` and `add` | They become custom elements, not native HTML deletion/insertion elements; no corresponding project rendering rules exist. | Distinguish erasure, strike-through, and placement according to the evidence. |
| `pb` | Folio boundaries are invisible. | Show quiet labels for 63r, 63v, 64r and link them to images. |
| Literal periods plus `pc` at line 48 | The data encode repeated stops. | Check the image and encode the observed punctuation once. |

The line-5 `span` is in the TEI namespace, where `span` is an analytical annotation element, not HTML's generic styling wrapper. Replace this spacing workaround with an appropriate transcription representation. [span](https://tei-c.org/release/doc/tei-p5-doc/en/html/ref-span.html), [space](https://tei-c.org/release/doc/tei-p5-doc/en/html/ref-space.html), [g](https://tei-c.org/release/doc/tei-p5-doc/en/html/ref-g.html), [choice](https://tei-c.org/release/doc/tei-p5-doc/en/html/ref-choice.html).

### 4. Give the text a restrained manuscript-oriented presentation

- Increase the usable transcription width. At the inspected three-panel size, most verse lines wrap. Offer a wider two-panel comparison and distinguish soft wraps from manuscript line breaks.
- Use a font with verified coverage for combining marks and medieval characters. The current CSS lists Junicode as a fallback; that does not establish that it is actually loaded. Select and test the font before committing to it.
- Use a warm, unobtrusive background, dark brown main text, and a darker neutral treatment for confirmed darker ink. The existing bold red `alt-ink` style does not reproduce the dark corrections visible on 63r.
- Anchor interlinear additions over their targets with sufficient vertical room. A generic `vertical-align: super` places text above the baseline but still advances the reading flow.
- Keep one fixed gutter for line numbers. The current `nth-child` selector restarts in each two-line couplet, making every odd line numbered rather than every fifth line.
- Make couplet spacing explicit: `tei-lg` needs an appropriate display rule before block spacing is dependable. Match witness indentation and initial proportions to the page, with literary reading layout available separately if desired.
- Retain line-click image navigation, with keyboard access and subtle focus styling. Put longer explanations in a note area so they do not masquerade as manuscript words.

These are design proposals. They have not been implemented or tested as new CSS.

## Foundation for encoding every witness

Use 3.7Y as the pilot: verify the 84-line sequence and all marks across the three folios; settle the encoding policy; implement the corresponding display behaviors; then validate and visually compare every encoded feature. Keep an explicit list of unresolved readings and review responsibility.

Recommended document organization is a TEI document per witness with poem divisions, or a documented `teiCorpus` arrangement. The site's current unnamespaced `witness`/`poem` wrapper is an application format, not a standard TEI root. A migration would also require adapting the loader. Give poems and lines stable witness-qualified IDs and connect `facs` to image surfaces/zones, reusing and checking the existing annotation coordinates.

Create a project ODD customization and generated schema, with Schematron checks for local reference resolution, identifiers, expected coverage, and documented exceptions. Pin the TEI release so validation remains reproducible. Automated validation can check structure and consistency; it cannot verify a manuscript reading.

Distinguish untranscribed material, witness absence, physical loss, and illegibility. O is a printed edition and LL is a digital comparison text; their source descriptions and transcription policies should reflect that. Cross-witness apparatus should follow the verified witness transcriptions.
